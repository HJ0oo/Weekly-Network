# 주간 통신 학습 루틴

## 0. 이 루틴의 목적 (가장 중요, 반드시 먼저 읽을 것)

이 리포트의 주인공은 **뉴스가 아니라 기초 개념**이다.

사용자는 통신 완전 초보자다. "기지국", "주파수", "RAN"이 정확히 무엇인지 모른다.
지금까지의 리포트가 실패한 이유는 정보가 부족해서가 아니라, **모르는 단어 위에 다른 모르는 단어를 쌓아 올렸기 때문**이다.
뉴스는 그 주에 배운 개념이 현실에서 어떻게 쓰이는지 보여주는 **보조 재료**일 뿐이다.

판단 기준은 하나다: **읽고 나서 개념 2개를 남에게 설명할 수 있으면 성공, 뉴스 10건을 읽었지만 아무것도 설명 못 하면 실패다.**

분량 기준: 기초 개념 설명 60% 이상 / 뉴스 30% 이하 / 나머지 10%.
뉴스가 많아서 개념 설명이 얕아졌다면 뉴스를 잘라내라. 반대로 하지 마라.

---

## 1. 시작 전 상태 확인 (이 순서대로)

1. 오늘 날짜를 확인한다.
2. `concepts/curriculum.md`를 읽는다 → 이번 주에 다룰 개념을 정한다 (아래 2절).
3. `sources/ACCESS-NOTES.md`를 읽는다 → **차단된 소스와 검증된 우회 경로를 미리 파악한다.** (매주 같은 실패를 반복하지 않기 위한 핵심 단계)
4. `reports/` 폴더의 가장 최근 리포트를 읽는다 → 이미 다룬 TTA 호수·논문·뉴스 중복 방지.
   - 최근 리포트 날짜가 오늘로부터 **7일을 넘게 지났다면(= 지난주 루틴이 실행되지 않았다면)**, 수집 범위를 그 공백까지 넓히고 리포트 맨 위에 한 줄로 밝혀라.
   - 폴더가 없으면 만든다.

---

## 2. 이번 주 개념 선정 규칙

- **커리큘럼 순서를 반드시 지켜라.** 뉴스가 화려하다고 뒤쪽 개념(6G, AI-RAN 등)을 앞당기지 마라. 순서를 어긴 설명이 지금까지 이해되지 않은 가장 큰 원인이다.
- 기본은 **2개**. 서로 이어지는 개념이면 2개, 하나가 무거우면 1개로 줄여도 된다. 3개 이상은 금지.
- 이번 주 뉴스를 이해하는 데 아직 안 배운 개념이 필요하다면, 그 개념을 앞당기지 말고 **"3문장 미리보기"**로만 처리하라. 정식 설명은 커리큘럼 순서가 올 때 한다.
- 개념 내용이 불확실하면 검색해서 확인하라. **추측해서 쓰지 마라. 틀린 설명은 없는 설명보다 나쁘다.**

---

## 3. 개념 설명 작성법 (리포트의 심장)

각 개념은 아래 6단계를 **이 순서 그대로** 서술한다. 개념 하나당 600~900자.

1. **문제부터**: 이 개념이 없으면 무슨 곤란한 일이 생기는가
2. **정의**: 그래서 이것은 무엇인가 (한 문장으로)
3. **동작 원리**: 실제로 어떻게 작동하는가 — 비유는 여기서 **딱 1개만**, 비유 뒤에는 **반드시 실제 메커니즘**을 이어 쓴다
4. **체감 사례**: 내 스마트폰, 내 집 와이파이에서 이것이 언제 일어나는가
5. **흔한 오해**: 초보자가 잘못 알기 쉬운 것 1가지를 바로잡는다
6. **한 줄 정리**: "결국 OOO는 ~하는 것이다"

그리고 각 개념 끝에 **"지난주에 배운 △△와 이렇게 이어진다"** 1문장을 붙인다. (첫 주는 생략)

---

## 4. 글쓰기 규칙 (하나라도 어기면 리포트 실패)

1. 약어는 첫 등장 시 **"쉬운 우리말 뜻(영문 풀네임, 약어)"** 3단 표기.
   예: `무선접속망(Radio Access Network, RAN) — 스마트폰과 통신사 장비를 무선으로 이어주는 구간`
2. 같은 리포트 안에서 약어가 다시 나와도 **최소 3번째 등장까지는 `RAN(무선접속망)`처럼 병기**하라.
3. **한 리포트에 새로 등장하는 용어는 7개 이하.** 넘으면 뉴스를 줄여라.
4. 한 문장에는 한 가지 생각만. 문장이 50자를 넘으면 자른다.
5. **수식·그리스문자 금지.** 숫자는 체감 단위로 환산하라. (예: "1Gbps" → "2시간짜리 영화 한 편을 약 8초에 받는 속도")
6. 영어 제목·문장을 그대로 두지 마라. 우리말로 옮기고 원문은 괄호에 넣는다.
7. **비유로 설명을 끝내지 마라.** 비유 → 실제 동작 설명 순서를 고정한다.
8. 기사체 금지. "주목받고 있다", "~로 알려졌다" 대신 무엇이 어떻게 동작하는지 서술하라.

## 5. 뉴스 수집 (보조 재료, 총 3~5건만)

선별 기준 세 가지를 모두 만족해야 넣는다.
① 이번 주 개념과 연결되는가 ② 초보자가 체감할 수 있는가 ③ **발행일이 확인되는가**

> **발행일 확인 규칙 (반드시 지킬 것)**
> 웹검색은 1~2년 전 기사를 최신인 것처럼 섞어서 내놓는다. 실제로 2025년 기사를 이번 주 소식으로 착각할 뻔한 적이 있다.
> 스니펫이나 본문에서 발행일을 확인하지 못한 항목은 **리포트에 넣지 마라.** 날짜가 애매하면 "<기사 제목> 날짜"로 한 번 더 검색하고, 그래도 불명확하면 버려라.

### 관심 분야 (우선순위)
1. AI + 통신 (AI-RAN, AI 네이티브 네트워크)
2. 무선/이동통신: 와이파이, 5G/6G — **사용자 이해도가 가장 낮은 분야이므로 반드시 기초부터**
3. 네트워크 전반

### 소스별 접근법 (아래는 실제로 검증된 방법이다. 실패하면 재시도 1회, 그래도 안 되면 즉시 건너뛴다)

**소스 1 — TTA ICT Standard Weekly (매주 월요일 발행)**
```bash
curl -s --max-time 20 "https://committee.tta.or.kr/data/weekly_list.jsp" \
  | iconv -f euc-kr -t utf-8//IGNORE | grep -o '제[0-9]*호[^<]*'
```
- `//IGNORE`가 **없으면 iconv가 조용히 빈 출력을 낸다.** 반드시 붙일 것.
- 본문 페이지(`weekly_view.jsp?news_id=<번호>`)의 내용 영역은 비어 있다. 실제 본문은 `weekly.tta.or.kr`의 PDF인데 **이 환경에서 차단(403)되어 있다.**
- 따라서 **제목만 확보**하고, 그 제목으로 웹검색해 배경을 1~2문장 보완하라. 추정이면 "제목 기반 추정"이라고 밝혀라.
- 목록은 최신 1건만 노출된다. **지난 호를 찾느라 시간 쓰지 마라.**

**소스 2 — arXiv 신규 논문 (개념과 연결될 때만 1~2편)**
- 1차 시도: `curl -sL --max-time 25 "http://export.arxiv.org/api/query?search_query=cat:cs.NI&sortBy=submittedDate&sortOrder=descending&max_results=40" -w "HTTP:%{http_code}\n"`
  - `-L`이 없으면 301만 돌아온다. 그리고 **429(요청 제한)가 자주 난다.**
- 429 또는 응답 없음이면 **즉시 2차 경로로 전환** (검증됨):
  1. WebFetch → `https://arxiv.org/list/cs.NI/YYYY-MM?skip=75` (skip 숫자를 키우면 최신 구간이 나온다. `show` 파라미터는 400 오류이므로 쓰지 마라)
  2. 관심 있는 논문마다 WebFetch → `https://arxiv.org/abs/<ID>` 로 제목·제출일·초록 확인
- arXiv 번호(YYMM.NNNNN)의 뒷자리는 그 달 전체 제출 순번이라 날짜에 비례한다. 하루 약 800~900편이므로 오늘이 N일이면 최신 번호는 대략 850×N. 지난 7일치는 그 위쪽 구간이다.
- **제출일은 반드시 abs 페이지에서 확인**하고 리포트에 적어라. 목록 순서만 믿지 마라.
- **긴 대기(`sleep 30` 등)는 하네스가 차단한다.** 기다리지 말고 경로를 바꿔라.

**소스 3 — 3GPP / ITU 표준화**
- `www.3gpp.org`는 이 환경에서 **차단**되어 있다. 1회만 시도하고 웹검색으로 전환하라.
- 검색어 예: `"3GPP RAN#<번호> outcome"`, `"3GPP Release 20 freeze"`, `"ITU-R WP5D IMT-2030 <월> 2026"`
- 검색에서 잘 잡히는 대체 소스: `6gfutures.substack.com`, `ericsson.com/blog`, `techblog.comsoc.org`
- 회의가 아직 진행 중이면 "진행 중, 결과는 다음 주 확인"으로 적고 **8절 다음 주 예고에 넣어라.**

**소스 4 — IITP 주간기술동향**
- 검증된 경로: WebFetch → `https://www.itfind.or.kr/publication/regular/weeklytrend/weekly/list.do`
  (최신 호수·발행일·기사 제목이 그대로 나온다)
- `iitp.kr` 목록 페이지는 자바스크립트라 보이지 않는다. 위 itfind 주소를 쓸 것.
- 통신·네트워크 관련 기사 **1건**이면 충분하다.

**소스 5 — 업계 뉴스 (WebSearch 중심)**
- 국내 언론사 상당수(edaily, boannews 등)가 본문 접근 차단이다. **검색 결과 스니펫으로 확인**하라.
- 검색어에 시점을 넣어라: `"<키워드> 2026년 <월>"`, 필요하면 구체 날짜를 나열.
- 국내: 전자신문, ZDNet Korea, 아이티데일리 / 해외: Light Reading, RCR Wireless

**소스 6 — IEEE 저널 (선택, 안 되면 미련 없이 버릴 것)**
- `ieeexplore.ieee.org`, `comsoc.org`, `spectrum.ieee.org` 모두 이 환경에서 **차단**되어 있다. 1회만 시도하라.
- 같은 연구의 arXiv 공개본이 있으면 그것으로 대체하라.
- **3주 연속 실패했다면 그 사실만 한 줄 적고 넘어가라.** 매주 같은 시도를 반복하지 마라.

### 소스 실패 시 공통 규칙
- 실패한 소스는 리포트 부록에 "확인 불가(사유 한 줄)"로만 적고 즉시 넘어간다. **전체 루틴을 중단하지 마라.**
- 이번 주에 **새로 차단됐거나 반대로 다시 열린 소스를 발견하면 `sources/ACCESS-NOTES.md`를 갱신하라.** 다음 주의 내가 같은 시간을 낭비하지 않도록 하는 것이 이 파일의 목적이다.
- 결과가 부실한 소스를 억지로 채우지 마라. **없는 내용을 지어내는 것은 절대 금지.**

## 6. 리포트 구조

파일: `reports/YYYY-MM-DD-telecom-weekly.md`

```
# 주간 통신 브리핑 — YYYY-MM-DD
> 이번 주 배울 것: (한 문장)

## 0. 30초 요약
## 1. 지난주 복습 (3문장 + 확인 문제 1개)
## 2. 이번 주 개념 ① — <개념 이름>
## 3. 이번 주 개념 ② — <개념 이름>
## 4. 개념으로 읽는 이번 주 뉴스 (3~5건)
## 5. 그 밖의 소식 (제목 + 한 줄 + 링크만)
## 6. 이해 점검 퀴즈 (5문제 + 정답·해설)
## 7. 이번 주 용어집 (새로 나온 용어만, 가나다순)
## 8. 다음 주 예고
## 부록: 이번 주 수집 상태 (소스별 성공/실패 한 줄)
```

작성 세부 규칙:
- **4절 뉴스 항목**마다 반드시 세 줄을 붙인다: `쉬운 설명` / `이번 주 개념 ①·②와의 연결` / `원문 링크(발행일 포함)`
- **5절**은 개념과 연결되지 않지만 알아둘 만한 소식. 제목 + 한 줄 + 링크만. 설명하지 마라.
- **6절 퀴즈**: 5문제. 답은 반드시 이번 리포트 본문에 설명된 내용이어야 한다. 해설에 "2절 참고"처럼 위치를 적어라.
- **난이도 표기**: 개념 섹션(2·3절)은 항상 초보자용이므로 별표를 붙이지 않는다. 뉴스 항목에만 ★(쉬움)~★★★(어려움)을 달고, ★★★에는 "건너뛰어도 좋음"을 덧붙인다.

### 그림 규칙 (개념마다 최소 1개 필수)

리포트는 **GitHub에서 읽는다.** GitHub 마크다운은 ` ```mermaid ` 코드블록과, 저장소에 올린 `.svg` 파일의 이미지 링크를 렌더링한다.
**마크다운 본문에 `<svg>` 태그를 직접 쓰면 GitHub가 지워버린다.** 반드시 파일로 저장해 이미지로 링크하라.

보여줄 내용에 따라 도구를 고른다:

| 보여줄 것 | 도구 |
|---|---|
| 구조·연결 관계 (기지국 구성, 코어망 연결) | Mermaid `flowchart` |
| 시간 순서·절차 (핸드오버 과정, 표준화 일정) | Mermaid `sequenceDiagram` 또는 `timeline` |
| **값의 크기와 범위 (신호 세기 dBm 눈금, 잡음 바닥, SNR 여유)** | **SVG 파일** |
| 파형·주파수 축 (변조, 대역폭, OFDM 부반송파) | **SVG 파일** |
| 항목 비교 (세대별 속도, 대역별 특성) | 마크다운 표 (이건 그림보다 표가 낫다) |

SVG 작성 규칙:
- 경로는 `assets/YYYY-MM-DD-<주제>.svg`, 리포트에서는 `![설명](../assets/파일명.svg)`로 링크한다
- **맨 먼저 흰색 배경 사각형을 깔아라.** 배경이 투명하면 GitHub 다크 모드에서 검은 글씨가 보이지 않는다
- 글자는 우리말로, `font-family="Apple SD Gothic Neo, Malgun Gothic, sans-serif"`, 13px 이상
- **축에는 반드시 단위를 적어라** (예: `신호 세기 (dBm)`). 숫자만 덩그러니 두지 마라
- 색은 3가지 이하. 색으로만 구분하지 말고 **글자 라벨을 함께** 붙여라 (색맹·흑백 출력 대비)
- 그릴 때는 `assets/_template.svg`를 복사해서 시작하라. 위 규칙이 이미 반영돼 있다

공통:
- 그림 바로 아래에 **"이 그림에서 볼 것: ~"** 한 줄 캡션을 반드시 단다
- 개념 하나당 그림 1~2개. **뉴스 섹션에는 그림을 넣지 마라** (그림 예산은 개념에 쓴다)
- 그림이 문장을 대신하지 못하면 빼라. 장식용 금지

## 7. 저장 전 자가 점검 (모두 통과해야 저장)

- [ ] 기초 개념 섹션(2·3절)이 뉴스 섹션(4·5절)보다 **길다**
- [ ] 모든 약어가 첫 등장 시 3단 표기(우리말 뜻 + 영문 풀네임 + 약어)로 정의됐다
- [ ] 새로 등장한 용어가 7개 이하다
- [ ] **개념 섹션마다 그림이 최소 1개** 있고, 그림마다 "이 그림에서 볼 것" 캡션이 붙어 있다
- [ ] SVG를 만들었다면 흰 배경 사각형이 깔려 있고, 축에 단위가 적혀 있다
- [ ] 뉴스 항목마다 "개념과의 연결" 한 줄이 있다
- [ ] **발행일을 확인하지 못한 뉴스가 섞여 있지 않다**
- [ ] 비유만 하고 끝난 설명이 없다
- [ ] 퀴즈 5문제의 답이 모두 본문에 설명돼 있다
- [ ] 50자를 넘는 긴 문장이 없다

하나라도 통과하지 못하면 **고쳐서 다시 점검하라.** 통과 못 한 채로 저장하지 마라.

## 8. 마무리

1. `concepts/curriculum.md`에서 이번 주 다룬 개념에 완료 표시(`[x]`)와 리포트 파일명을 기록한다.
2. `sources/ACCESS-NOTES.md`를 갱신한다 (접근 상태에 변화가 있을 때만).
3. 변경 파일을 커밋하고 지정된 브랜치에 푸시한다.
4. 터미널에 5줄 이내로 출력한다: 리포트 경로 / 이번 주 배운 개념 2개 / 가장 중요한 뉴스 1건.
